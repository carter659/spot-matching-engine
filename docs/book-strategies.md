# 币安持续订单簿策略

入口：mock 首页 → 盘口策略（/strategies.html）。新增默认暂停；启动后持续运行，关闭页面不影响后端执行。仅手动暂停或删除停止，运行状态跨重启恢复。

每个交易对一个策略，最多 20 个策略；每侧 1–50 档，数量倍率 0.00000001–1000，最多 8 位小数。运行中可修改档位和数量倍率，仅调整参数变化导致的差异档位，替换委托须等待撤单回执。交易对不可直接修改，请另建策略。

使用币安公开现货 /api/v3/depth；不向币安下单。默认每秒调度所有活跃策略（fixedRate），网络慢或限流会延迟，不重叠执行。首次保存盘口和投递计划，再通过 RabbitMQ 投递本地 LIMIT/GTC 买卖单；每次以“方向 + 价格”为键比较实际剩余挂单与源盘口。仅序号变化不会撤单；数量相同保留原 ID，源档位消失撤销，数量变化先撤后补，新档位或已成交缺档补单。撤单意图先持久化，收到可靠结果后才补单，期间保留所有未变化委托。不会改变手动委托。行情失败保留原挂单并自动重试；限流遵守 Retry-After。并非逐条实时盘口同步。

价格按本地精度买向下、卖向上取整，数量乘倍率后向下取整，同价合并，小于一手跳过。需要 server 启用对应交易对。

MySQL matching_mock：mock_book_strategy 保存配置与当前运行阶段；mock_strategy_snapshot 保存每轮源盘口、参数和计划；mock_strategy_order 保存策略、盘口、commandId、实际雪花订单 ID 及状态关联。JPA 管理表结构，MyBatis Plus 读写。删除策略后仍保留成交等非撤单记录；页面“记录”展示最近 20 轮关联委托，数据库每 10 秒清理确认已撤单的策略委托记录，解除快照关联，并每批最多清理 100 个无关联委托的快照；原始命令、撤单回执和成交数据保留。旧版本未保存的源盘口不能补造，迁移记录标记 legacy。

重启后保留运行策略的原委托和待撤标记，再继续差异同步；手动暂停中的策略完成撤单后保持暂停。仅支持一个 mock 实例执行同一数据库内的策略。

server 每 5 秒通过 Kafka 补发真实内存订单簿，供新连接或故障恢复后的 mock 缓存恢复；不产生额外订单。

同一委托可被多个盘口快照复用，快照 plan 保存关联 commandId，mock_strategy_order 保存其实际雪花订单 ID 和状态。买卖交替投递，单档发布失败不会阻断另一方向。真实成交会消耗挂单，下一轮按剩余数量补齐；不撤销其他手动单，也不伪造双边盘口。

清理先持久化移除策略当前计划及待撤标记中的已确认撤单引用，再删除策略历史，避免重启后重建已清理记录。未收到撤单回执的委托仍保留。MySQL 删除释放的页空间可供复用，InnoDB 表文件不一定立即缩小。
